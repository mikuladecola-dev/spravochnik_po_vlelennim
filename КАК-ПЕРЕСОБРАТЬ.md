# Как пересобрать сайт

## Коротко

```
python3 build_sprav.py     # справочник из статей и правок
python3 build_site.py      # сайт из справочника
```

Первая команда нужна, только если менялся справочник. Вторая — всегда.
Ручной работы после них нет: сайт целиком перезаписывается заново.

Проверка (необязательно, но дёшево):

```
python3 check_site.py      # открывает сайт в браузере и щёлкает по нему
```

## Что откуда берётся

| Что на сайте | Откуда |
|---|---|
| Статья | `spravochnik/<раздел>/<ID>-имя.md` |
| Разделы статьи | заголовки второго уровня, с теми же якорями (`VS-0002#S07`) |
| Связи под разделом | строка `**Связи раздела** — …` в конце раздела |
| Цитаты | блоки `> …` в статье |
| Пробелы | всё содержимое раздела «Пробелы» |
| Машинные заметки | блоки `> ⚙ …` и хвост между метками `МАШИННЫЕ ЗАМЕТКИ` |
| Вводный текст | всё, что стоит до первого заголовка второго уровня |
| Списки в меню | `kb/_raw/registry.json` плюс `_sistema/gruppy.json` |
| Варианты имени для поиска | поле `aliases` записи в реестре |
| Дословный исходник | `kb/…` — своей страницей на каждую запись базы |

## Обычный цикл работы

1. **Дочитали свежий экспорт переписки.** `python3 chunk.py` → окна,
   воркфлоу чтения → находки, `python3 render.py` → база `kb/`.
2. **Написали новые статьи.** `python3 prep_uni.py "<Вселенная>" <префикс>` соберёт
   списки и пачки заданий, воркфлоу `wf_sprav_a.js` и `wf_sprav_b.js` их напишут.
3. **Пересобрали:** `python3 build_sprav.py && python3 build_site.py`.

## Поправка от руки

Правки живут отдельно от авто-слоя и пересборку переживают:
пишите в `spravochnik/_sistema/pravki/<ID>.md`. Авто-слой при пересборке
заменяется целиком, правки — никогда.

Если поправка касается самого текста статьи, а не примечания к ней, —
меняйте `spravochnik/_sistema/auto/<ID>.md`. Он тоже переживает пересборку
справочника; его переписывают только агенты, когда статью пишут заново.

## Что где лежит на выходе

```
site/
  index.html          заглавная: вселенные и разделы
  <ID>.html           статья (1043 штуки)
  kb/<файл>.html      дословный исходник записи базы (1426 штук)
  site.css            оформление: макет + добавленное
  site.js             поведение: макет + подстановка данных
  lib.js              списки для меню и глобального поиска
```

Сайт статический: ни сервера, ни базы. Можно открыть `index.html` файлом,
можно положить папку на любой хостинг как есть.


## Что сборщик делает намеренно

Эти решения приняты после сверки сайта со статьями — не трогайте их «на глаз».

- **Проза выводится дословно.** В разделе «Текст» строка «- реплика» — это тире прямой
  речи, а не пункт списка, и переносы строк значимы. Такой текст не проходит через
  markdown вовсе: экранируется и разбивается по `<br>`. Через markdown реплики
  слипались в один пункт и утягивали за собой следующие абзацы.
- **Цитаты тоже дословные.** Блок `> …` собирается тем же способом.
- **Подписи под цитатами не ставятся.** Автор и дата уже стоят в тексте рядом.
- **Внутрь ``` сборщик не лезет.** Ни разметка, ни расстановка пустых строк:
  в дословных сводах авторов номер и пустая строка бывают значимы.
- **Подзаголовка в шапке нет.** Там стоял машинный пересказ, его убрали.
- **Числа в шапке названы «записей в базе» и «записи: дата → дата».** Они считаются
  по реестру базы и могут не совпадать с числами внутри статьи, которые агент считал
  по прочитанному. Названы так, чтобы не выдавать одно за другое.
- **Редакционная рамка служебных документов** идёт классом `.ed` — серым, без жёлтой
  полосы, чтобы не читалась как дословная цитата.

## Правила, которые нельзя нарушать при правке оформления

Сайт открывается в WebView внутри мессенджера, а не только в браузере.

1. `env(safe-area-inset-*)` **не ставить внутрь `calc()` через переменную** —
   WebView не понимает и выбрасывает всё свойство целиком. Пишите обычное значение
   первой строкой, вариант с вырезом — отдельной строкой следом:

   ```css
   article{padding:0 16px 90px}
   article{padding-bottom:calc(90px + env(safe-area-inset-bottom,0px))}
   ```

2. Скрытые панели прятать полностью (`visibility:hidden`, `pointer-events:none`),
   а не одной прозрачностью: иначе WebView перерисовывает их каждый кадр.
3. Никаких измерений геометрии на каждое событие прокрутки. Размеры считаются
   один раз в `layout()` — при загрузке и повороте экрана; обновление идёт
   через `requestAnimationFrame`, ползунок двигается только трансформацией.
4. Ничего не класть поверх полосы прокрутки справа: `main` держит отступ
   шириной `--rail`, полоса ловит касания сама.
5. В светлой теме жёлтым не пишется текст — жёлтый только фон и линии.

## Где что править в сборщике

| Задача | Место в `build_site.py` |
|---|---|
| Добавить вкладку в меню | список `TABS` |
| Изменить факты в шапке статьи | `facts_for()` |
| Изменить подзаголовок | `sub_for()` |
| Разметка страницы | `page()` |
| Как текст статьи становится HTML | `blocks_to_html()` |
| Куда ведут ссылки | `href_for()` |

Оформление — в `site_src/mockup.css` (эталон макета, не трогать)
и `site_src/extra.css` (то, чего в макете не было). Поведение — `site_src/site.js`.
Сборщик просто склеивает их в `site/site.css` и копирует `site.js`.
